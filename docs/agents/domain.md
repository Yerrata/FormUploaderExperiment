# Domain docs

This repository uses a single domain context.

## Before exploring

Read `CONTEXT.md` when it exists and any relevant architecture decisions under `docs/adr/`. If they do not exist, proceed without treating their absence as an error.

## Vocabulary

Use the canonical terms recorded in `CONTEXT.md`. When a required term is ambiguous or missing, resolve it through domain modelling before adding it.

## Architecture decisions

Surface any conflict with an existing architecture decision. Create an ADR only for a decision that is hard to reverse, surprising without its context, and the result of a genuine trade-off.
